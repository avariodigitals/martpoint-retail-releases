Architecture & technology

MartPoint is a browser-based retail application with a traditional server-rendered core, a responsive frontend, and a Progressive Web App layer for offline resilience.

LayerTechnologyRole
BackendPHP 7.4+ / CodeIgniter 3Application logic, routing, controllers, models, sessions
DatabaseMySQL 5.7+ / MariaDBTransactional data, settings, audit logs, migrations
FrontendAdminLTE 2, Bootstrap 3, jQueryDesktop dashboard, forms, tables, reports
Mobile shellCustom mobile views + CSS varsPhone and tablet-portrait UX with bottom navigation
Offline layerService Worker + IndexedDBQueue sales/purchases and sync when back online
AI / ChatCustom conversational engineMartPoint Assist for natural-language queries
PaymentsStripe, Paystack, InstamojoCard and online payment processing (configurable)
DocumentsDOMPDF / TCPDFInvoices, receipts, reports, PDF exports
QR / Barcodeschillerlan/php-qrcodeBarcode/QR generation and scanning support

Web-first

No desktop installer. Staff open a browser, sign in, and start selling. Chrome is recommended.

Multi-tenant by store

Each store has its own settings, users, stock, and permissions while sharing the same codebase.

Permission model

Role-based access control with per-feature permissions and PIN-based approvals for sensitive operations.

Security principles

  • HTTPS in production. SSL certificate required.
  • Passwords hashed; sessions managed server-side.
  • Role-based access limits what each user can see and do.
  • PIN approvals protect discounts, returns, and sensitive settings.
  • No API keys, tokens, or passwords in this document.
  • Credentials belong only in server-side config files and are never exposed in URLs.
  • Regular backups of the database and uploaded files are essential.

Offline PWA behaviour

  • Sales and purchases can be queued in IndexedDB when offline.
  • A pending badge shows unsynced transactions.
  • Sync retry runs automatically when connectivity returns.

Update system

MartPoint includes a one-click auto-update engine designed to keep production instances current with minimal downtime.

1

Backup

Create a full database and file backup before starting.

2

Download

The updater fetches the release package from the configured channel.

3

Verify & apply

Checksums are verified, files are replaced, and pending SQL migrations run idempotently.

4

Finalize

Cache is cleared and the new version is confirmed in settings.

Fresh installation

Estimated time: 30–45 minutes. These steps assume a standard Linux/Apache/Nginx or LAMP/LEMP stack.

1

Obtain the release package

Request the latest MartPoint source package from your partner contact. Place it on the server and extract it into the web root.

2

Create the database

CREATE DATABASE martpoint_db
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'martpoint_user'@'localhost' IDENTIFIED BY 'STRONG_PASSWORD';
GRANT ALL PRIVILEGES ON martpoint_db.* TO 'martpoint_user'@'localhost';
FLUSH PRIVILEGES;
3

Import the seed database

From the release package, import the provided seed.sql (or equivalent base dump) to create tables and default records.

mysql -u martpoint_user -p martpoint_db < /path/to/seed.sql
4

Configure the application

Edit application/config/database.php and application/config/config.php with your values.

$db['default']['hostname'] = 'localhost';
$db['default']['username'] = 'martpoint_user';
$db['default']['password'] = 'STRONG_PASSWORD';
$db['default']['database'] = 'martpoint_db';

$config['base_url'] = 'https://your-domain.com/';
$config['app_name']  = 'MartPoint';
$config['app_version'] = '4.0.9';
5

Run database migrations

Migrations run automatically on first access, or you can apply the supplied SQL files manually.

mysql -u martpoint_user -p martpoint_db < /path/to/migrations/*.sql
6

Set file permissions

chmod -R 755 application/ release_upload/
chmod -R 777 application/cache/ application/logs/ uploads/
7

Configure the web server

Apache: ensure mod_rewrite is enabled and .htaccess rules are active. Nginx: route all non-file requests to index.php.

8

Access and verify

Open the site URL. Log in with the default admin credentials supplied in the partner package and immediately change the password.

Verification, rollback & support

Post-installation verification

Run through this checklist before handing the system to users.

  • Application loads without errors
  • Login page displays and sessions work
  • Dashboard loads with KPIs
  • POS adds items and completes a test sale
  • Customer management opens
  • Sales report generates and exports
  • Mobile views render on a phone
  • Marketing module opens
  • Database migration version matches app version
  • Error logs are clean

Rollback procedure

Always back up before an update. If a deployment fails, restore the previous state.

  1. Stop the web server or enable maintenance mode.
  2. Restore application files from the pre-update backup.
  3. Restore the database from the pre-update dump.
  4. Clear application/cache/.
  5. Restart the web server and verify.

Troubleshooting quick reference

White screen of death
Check application/logs/, enable log_threshold = 4 temporarily, and validate php -l index.php.
Database connection error
Verify MySQL is running, the database exists, the user has privileges, and credentials in database.php are correct.
POS not loading
Clear cache, run php -l application/controllers/Pos.php, and confirm sales-related tables exist.
Permission denied
Ensure cache, logs, and uploads directories are writable by the web server user (e.g. www-data).
