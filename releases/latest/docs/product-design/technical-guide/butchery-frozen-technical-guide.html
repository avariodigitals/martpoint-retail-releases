Architecture

What the module adds

The Frozen Food & Butchery module is an industry-isolated, feature-flagged add-on. It keeps the core MartPoint product untouched while adding butcher and cold-chain workflows for licensed stores.

New tables

Templates, template cuts, received carcasses, cut records, shares, freezer locations and temperature logs.

Item fields

is_carcass, carcass_template_id, portion_of_item_id, storage_temp_min, storage_temp_max, thaw_time_hours, use_within_hours_after_thaw, frozen_shelf_life_days.

Feature flags

meat_butchery_workflow and frozen_food_cold_chain require warehouse_module() and must be in the store feature list.

Mobile shell

Dedicated mobile views with custom selects, bottom nav, alerts and MartPoint Assist chat on every screen.

Database

Run the migrations

The module uses the existing CodeIgniter migration system. Run from the project root to apply the schema.

php index.php migrations

Expected output:

Migrations complete. Current version: 24

Migration 015

Adds butcher and frozen columns to db_items. Safe to re-run because it checks for existing columns.

Migration 016

Creates the butchery and frozen tables including carcasses, cuts, shares, freezers and temperature logs.

Configuration

Enable the module per store

The feature must be enabled per store. Use the Business Profile page for new stores or SQL for existing deployments.

1

Business Profile (recommended)

Go to Settings → Business Profile. Choose Butcher / Meat Shop or Frozen Foods Retailer. In the Feature Flags tab, enable Warehouse, Meat / Butchery Workflow and/or Frozen Food Cold Chain. Save and refresh.

2

Force via SQL

If the UI is not reachable, run this for the target store:

UPDATE db_store SET feature_flags_json = JSON_SET( COALESCE(feature_flags_json, '{}'), '$.warehouse', true, '$.meat_butchery_workflow', true, '$.frozen_food_cold_chain', true ) WHERE id = {store_id};
Note: Replace {store_id}. If MySQL does not support JSON_SET, set the raw JSON string directly.

Integration

Item form & stock

The item add/edit form now shows a Butchery & Frozen card. Completion of a cutting worksheet auto-creates sellable cut items.

Item fields saved by Items_model::save_record()

  • is_carcass
  • carcass_template_id
  • portion_of_item_id
  • storage_temp_min / storage_temp_max
  • thaw_time_hours
  • use_within_hours_after_thaw
  • frozen_shelf_life_days

Cut worksheet creates sellable stock

Butchery_model::complete_cut_to_stock($received_carcass_id, $cuts) does the following:

  • Generates an item_code such as CUT-{carcass_id}-{n}.
  • Creates or reuses category Butchery Cuts and unit KG.
  • Sets stock to the cut's actual weight in kilograms.
  • Carries purchase price, sales price and carcass lot number.
  • Re-completing a carcass replaces prior cut items with the same generated code.

Compliance & go-live

Mobile & deployment

All mobile butchery views follow the MartPoint mobile rules and are gated by the same flags as the desktop module.

Mobile shell

Uses mobile/ views, not mp_layout. Includes store name in the title, custom mp-select, bottom nav, alert and chat partials.

Feature isolation

The module only appears for stores with the correct business profile and flags. It does not affect supermarkets, pharmacies or other verticals.

Deployment checklist

  • PHP 7.4 configured on the server.
  • Migrations run to version 24.
  • Butchery/frozen flags enabled for the target store.
  • warehouse flag enabled.
  • Menu appears in sidebar and mobile More.
  • Test receive → cut → share → temperature.
  • Verify cuts appear as sellable items.
  • Test POS and online checkout.
