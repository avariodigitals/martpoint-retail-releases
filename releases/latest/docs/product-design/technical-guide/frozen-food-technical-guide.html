Architecture

What the cold chain adds

Frozen food retail uses the cold-chain half of the Butchery & Frozen module: freezer locations, temperature logs and per-item storage rules. It shares the same migrations and sidebar entry as the butchery workflow, but the carcass screens are not needed.

Tables used

db_freezer_locations and db_temperature_logs. Migration 016 also creates the carcass tables, which stay unused unless meat_butchery_workflow is enabled.

Item fields

storage_temp_min, storage_temp_max, thaw_time_hours, use_within_hours_after_thaw, frozen_shelf_life_days on db_items.

Feature flag

frozen_food_cold_chain requires warehouse_module() and must be in the store feature list. The frozen_foods_retailer preset enables it automatically.

Mobile shell

/mobile/butchery_coldchain is a dedicated mobile view — custom selects, bottom nav, alerts and MartPoint Assist chat.

Preset applied: Choosing Frozen Foods Retailer sets theme market_fresh, dashboard frozen_foods, and relabels items as Product / Pack.

Database

Run the migrations

The module uses the existing CodeIgniter migration system. Run from the project root to apply the schema.

php index.php migrations

Expected output:

Migrations complete. Current version: 24

Migration 015

Adds the storage, thaw and shelf-life columns to db_items. Safe to re-run because it checks for existing columns.

Migration 016

Creates db_freezer_locations and db_temperature_logs alongside the carcass tables. Each CREATE TABLE is guarded by table_exists.

Verify after migrating

SHOW COLUMNS FROM db_items LIKE 'storage_temp_min'; SHOW TABLES LIKE 'db_freezer_locations'; SHOW TABLES LIKE 'db_temperature_logs';

Configuration

Enable the module per store

The feature must be enabled per store. Use the Business Profile page for new stores or SQL for existing deployments.

1

Business Profile (recommended)

Go to Settings → Business Profile. Choose Frozen Foods Retailer. In the Feature Flags tab, enable Branch / Stock Transfer (warehouse), Frozen Food Cold Chain, Batch Tracking, Expiry Tracking and Multi-Unit Selling. Save and refresh.

2

Force via SQL

If the UI is not reachable, run this for the target store:

UPDATE db_store SET feature_flags_json = JSON_SET( COALESCE(feature_flags_json, '{}'), '$.warehouse', true, '$.frozen_food_cold_chain', true, '$.batch_tracking', true, '$.expiry_tracking', true, '$.multi_unit_selling', true, '$.meat_butchery_workflow', true ) WHERE id = {store_id};
Note: Replace {store_id}. If MySQL does not support JSON_SET, set the raw JSON string directly. If db_store_industry_settings exists, apply the same update to its row — it is checked first. meat_butchery_workflow is included because the desktop /butchery/* screens are gated by it — see next page.

Routing

URLs and feature gating

Cold-chain screens live under the shared Butchery controller. The sidebar shows Butchery & Frozen when either meat_butchery_workflow or frozen_food_cold_chain is enabled.

Desktop routes

  • /butchery
  • /butchery/freezers
  • /butchery/temperature
  • /butchery/receive — butchery only
  • /butchery/cut/{id} — butchery only
  • /butchery/shares — butchery only

Mobile routes

  • /mobile/butchery_coldchain — freezers + temperature
  • /mobile/butchery — butchery only
  • /mobile/butchery_form — butchery only
  • /mobile/butchery_cut/{id} — butchery only
  • /mobile/butchery_shares — butchery only
Gating caveat: Every desktop /butchery/* route calls _check_feature('meat_butchery_workflow'), so desktop Freezers and Temperature require meat_butchery_workflow even though they are cold-chain features. Mobile butchery_coldchain accepts either flag. For a frozen-only store, enable both flags for desktop access — the carcass screens can simply be left unused.

Integration

Item form, alerts & stock

When frozen_food_cold_chain (or meat_butchery_workflow) is on, the item add/edit form shows a Butchery & Frozen card. It is hidden for service, digital, course and membership product types.

Item fields saved by Items_model::save_record()

  • storage_temp_min / storage_temp_max
  • thaw_time_hours
  • use_within_hours_after_thaw
  • frozen_shelf_life_days
  • is_carcass, carcass_template_id, portion_of_item_id — unused for pure frozen retail

Temperature log statuses

Each reading on db_temperature_logs is saved with a status:

  • normal — reading inside the freezer's min/max range.
  • warning — reading below temp_min or above temp_max.
  • alert_sent flag is stored per row for notification workflows.

Inventory features that work alongside

  • batch_tracking + expiry_tracking — batch and expiry per carton; Stock Rotation screen under Operations.
  • multi_unit_inventory + multi_unit_selling — sell the same item by carton, pack or kilo.
  • pos_retail_button / pos_wholesale_button — quick price switching at the POS.

Compliance & go-live

Mobile & deployment

The cold-chain mobile view follows the MartPoint mobile rules and is gated by the same flags as the desktop module.

Mobile shell & isolation

/mobile/butchery_coldchain uses mobile/ views, not mp_layout — store name in the title, custom mp-select, bottom nav, alert and chat partials. The module only appears for stores with the right profile and flags; other verticals are unaffected.

Deployment checklist

  • PHP 7.4 configured on the server.
  • Migrations run to version 24.
  • warehouse flag enabled.
  • frozen_food_cold_chain + meat_butchery_workflow on for desktop.
  • Butchery & Frozen appears in sidebar and mobile More.
  • Create a freezer; log in-range and out-of-range readings.
  • Verify the Butchery & Frozen card on the item form.
  • Test a weighted POS sale and an online checkout.
